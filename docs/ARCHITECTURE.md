# TraceRAG 架构说明

TraceRAG 把企业知识问答拆成可独立观察和评测的阶段。生成模型只是最后一个可替换步骤；检索、证据契约、降级、trace 和评测决定系统能否定位错误并长期维护。

```text
Vue 3 SPA -> FastAPI/JWT -> SQLAlchemy -> MySQL
                    |
                    +-> query normalize
                    +-> BM25 retrieve + rank
                    +-> grounded generate -> DeepSeek (optional)
                                           -> deterministic fallback
                    +-> sources + trace + confidence
```

## 检索链路

1. Query rewrite：压缩多余空白，抽取英文 token、中文单字和相邻双字词。
2. Retrieve：从 `PUBLISHED` 知识文档和支持工单组装语料，按请求实时计算词项统计。
3. Rank：使用 BM25 的 IDF、词频饱和和文档长度归一化计算得分，选择前 4 条并以最高分归一化。
4. Generate：存在证据时调用 DeepSeek 兼容接口；未配置或调用失败时，用同一证据生成确定性摘要。
5. Grounding：返回来源编号、片段、相关度、置信度、运行模式、`traceId` 与阶段耗时，并把轨迹摘要写入 MySQL。

## BM25 的选择与边界

当前数据集规模小，文档内容以产品规则、错误码和操作说明为主，精确术语具有较强区分度。BM25 无需额外向量服务，分数来源可以解释，也便于在免费部署环境稳定复现。中文分词采用单字和双字词是有意的轻量方案：它能覆盖短查询中的局部词组，但不具备词典分词、同义词扩展或语义召回能力。

因此系统不会把 BM25 描述成向量检索。出现同义改写、跨段推理或长文档主题匹配时，召回可能下降。演进顺序应是先补充分块和评测用例，再比较 BM25、embedding 和混合召回；只有离线指标证明收益后，才引入向量库与 reranker。

## 证据约束与降级

生成请求只包含用户问题和 Top 4 证据片段，系统提示要求关键结论引用资料编号，证据不足时拒答。这个约束降低脱离资料生成的概率，但不能从理论上保证模型逐句忠实，因此接口同时返回原始来源供用户核对。

DeepSeek 调用设置 5 秒连接超时和 18 秒总请求超时。未配置密钥、没有证据、超时、限流或响应解析失败时，系统使用 `fallback_answer` 从证据首句生成确定性摘要，并在响应中明确返回 `GROUNDED_FALLBACK`。降级保证服务可用性，不代表与模型回答具有相同表达能力。

## Trace 与置信度

每次查询生成唯一 `traceId`，记录问题、模式、来源数量、置信度、总耗时和创建时间。接口还返回查询标准化、检索排序、证据生成三个阶段的耗时与说明，便于判断问题发生在“没召回”“排序靠后”还是“生成失败”。

当前置信度取前两条归一化检索得分的平均值，是面向界面的启发式指标，并非经过概率校准的正确率。若用于真实决策，需要基于标注集做阈值校准，并将低置信度与无答案拒答策略绑定。

## 评测

- Recall@4：六条固定问题中，期望文档进入前 4 条的比例，用于衡量召回覆盖。
- MRR：期望文档排名倒数的均值，用于区分“召回到了”和“排在第一位”。
- Citation Coverage：当前记录回答是否绑定检索来源，尚未执行逐句蕴含判断。

评测运行结果以独立记录写入数据库，保留运行时间和用例数。固定集可以发现明显回归，但六条用例仍然很小；生产系统应按业务域扩充困难负样本、无答案问题和权限过滤场景，并把检索指标与人工答案质量分开评估。

## 数据与部署

FastAPI 负责认证、知识库、查询和评测接口，SQLAlchemy 保存文档、工单、轨迹和评测运行。Vue 由同一个容器提供静态资源，减少免费环境的服务数量。MySQL 位于独立 TiDB Cloud schema，Render 休眠和容器替换不会清空数据。

生产演进应优先增加租户与文档级权限过滤、文档分块和数据同步，再通过评测决定是否加入 embedding、向量库与 cross-encoder reranker。之后还需要 Prompt/模型版本、敏感信息过滤、在线反馈、异步评测和指标告警。当前仓库不把这些计划写成已实现能力。
